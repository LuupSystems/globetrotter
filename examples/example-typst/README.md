### Globetrotter Typst example

This example renders an invoice with translations generated by the `typst` output and the
[globetrotter Typst runtime](../../runtime/typst/globetrotter).

`globetrotter.yaml` generates `generated/translations.typ` from `translations.toml` and declares the
example directory as its usage root, so `globetrotter lint` scans `invoice.typ` for the keys it
uses. With `calls: deny`, a call to an undefined key or with mismatched arguments fails the lint
even when it sits in a branch the document never renders. `invoice.typ` imports the runtime by path, registers a `pluralize` helper, and calls
`t("key", name: value)`; the concatenated `t("invoice.status." + status)` keeps every
`invoice.status.*` key in use under the default dynamic policy.

```bash
# From the repository root; requires the typst CLI.
task example:typst

# Or step by step, from this directory:
globetrotter --config globetrotter.yaml
globetrotter lint --config globetrotter.yaml
typst compile --root ../.. invoice.typ generated/invoice.pdf
typst compile --root ../.. --input lang=de invoice.typ generated/invoice-de.pdf
```

`--root ../..` lets the document import the runtime from `runtime/typst/globetrotter`. A project outside
this repository vendors `lib.typ` or installs the package as `@local/globetrotter:0.1.0`.
