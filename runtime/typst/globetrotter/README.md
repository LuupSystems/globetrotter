# globetrotter for Typst

Renders translations from a module generated by
[globetrotter](https://github.com/LuupSystems/globetrotter)'s `typst` output. The generated module
holds only data; this package checks each call against the declared arguments and renders the
templates with a small Handlebars subset.

```typst
#import "@local/globetrotter:0.1.0": translator
#import "translations.typ" as catalog

#let t = translator(catalog, "en", helpers: (
  pluralize: (word, count) => if count == 1 { word } else { word + "s" },
))

#t("greeting", name: "Ada")   // "Hello Ada!"
#t("cart.items", count: 3)    // "3 items"
```

The package is not published to Typst Universe. Copy this directory to
`{data-dir}/typst/packages/local/globetrotter/0.1.0` to import it as `@local/globetrotter:0.1.0`, or
vendor `lib.typ` and import it by path. Its version follows the module format it reads, not the
globetrotter CLI.

## API

`translator(module, lang, helpers: (:))` returns `t(key, ..arguments)`.

- `module` is the generated module, imported with `#import "translations.typ" as catalog`, or a
  dictionary with the same fields.
- `lang` is one of the module's `languages`.
- `helpers` maps helper names to functions. A helper receives the evaluated parameters of
  `{{name param ...}}` positionally and returns a `str`, number, boolean, or `none`. Close over
  anything else it needs, such as the language.

`t` returns a `str`. Pass arguments by name: `t("greeting", name: "Ada")`.

## Checks

Every check panics, so a faulty call fails the document's compilation:

- an unsupported module format version or template engine, an unknown language, or a helper that
  is not a function
- an unknown key, a positional value, or a missing or unexpected argument
- an argument whose type contradicts its declared type
- an unsupported template construct, a reference to an undeclared argument or missing field, an
  unknown helper, or a value that cannot be rendered as text, such as content

| Declared type | Accepted Typst types |
|---|---|
| `string`, `isodatetime` | `str` |
| `number`, `integer` | `int`, like the other generated bindings |
| `float` | `int` or `float` |
| `boolean` | `bool` |
| `any` | every type |

## Supported Handlebars subset

A key without arguments is a literal and is returned verbatim. A module with `engine: none` renders
only literals.

| Construct | Behavior |
|---|---|
| `{{path}}`, `{{{path}}}` | The value as plain text. Neither form escapes HTML; Typst sets a `str` as text. |
| `{{[arg-name]}}`, `{{user.name}}`, `{{user.[home town]}}` | Segment literals and dictionary fields of an argument. |
| `{{#if path}}…{{else}}…{{/if}}` | Handlebars truthiness: `none`, `false`, zero, `""`, and `()` are false. |
| `{{#unless path}}…{{else}}…{{/unless}}` | The inverse of `if`. |
| `{{! comment }}`, `{{!-- comment --}}` | Removed. |
| `{{name param …}}` | Calls a registered helper with paths and string or number literals. A bare `{{name}}` calls a registered helper before it reads an argument of that name. |

Numbers render with an ASCII minus sign and booleans as `true` or `false`; `none` renders as empty
text. Everything else, including `{{#each}}`, `{{else if}}`, partials, whitespace control, `this`,
`../`, `@` data variables, subexpressions, hash arguments, and `\{{` escapes, panics with a message
naming the key and the construct.

## Tests

`tests/render.typ` asserts every construct against `tests/translations.typ`, which globetrotter
generates from `tests/catalog.toml`. The repository's `task test:typst` compiles it and checks that
each invalid call panics with the expected message.
